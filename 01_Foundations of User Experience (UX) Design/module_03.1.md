## 1. Design Sprint Fundamentals

- **Definition**: A time-bound process with five phases typically spread across five full, 8-hour days.
- **Goal**: Solve critical, complex design challenges through designing, prototyping, and testing ideas directly with users.
- **Core Philosophy**: Highly collaborative, distractionless/gadgetless, and inclusive. It brings together cross-functional team members (engineers, marketers, product managers, designers) with diverse perspectives.

### When to Run a Design Sprint

- When there are many potential solutions to a challenge.
- When cross-functional input is necessary.
- When the challenge scope is wide enough to justify a dedicated week.

## 2. Key Benefits of Design Sprints

| Benefit | Description |
| --- | --- |
| **Puts the User First** | Keeps user needs at the center of the challenge |
| **Saves Time & Money** | Condenses months of decision-making into a single week and prevents costly missteps before launch |
| **Equal Voice / Inclusivity** | Values input from everyone in the room regardless of rank (from interns to senior stakeholders) |
| **Lowers Risk** | Gathers real user feedback on prototypes *before* making expensive engineering commitments |
| **Versatile** | Can be scheduled at any stage of a project when complex challenges arise |

## 3. The 5 Phases of a Design Sprint

| Day | Phase | Activities |
| --- | --- | --- |
| **Day 1** | **Understand** | Map out the challenge, review research, conduct expert lightning talks, perform "How Might We" (HMW) exercises, build empathy maps, and pick a clear target focus |
| **Day 2** | **Ideate** | Research existing products for inspiration, generate rough ideas, execute **Crazy Eights** (sketching 8 distinct ideas in 8 minutes), and create detailed anonymous solution sketches. Recruit target users now for Day 5 testing |
| **Day 3** | **Decide** | Critique and vote on anonymous solution sketches, choose the best idea (or combine elements), and create a step-by-step storyboard for the prototype |
| **Day 4** | **Prototype** | Select tools, assign specific roles (**Makers**, **Stitcher**, **Writer**, **Interviewer**, **Asset Collector**), and build a realistic, workable prototype for user testing |
| **Day 5** | **Test** | Put the working prototype in front of real target users (5 participants), observe interactions, conduct interviews, take grid notes, and debrief as a team |

## 4. Planning a Design Sprint (7 Steps)

1. **User Research**: Gather initial research on the focus area.
2. **Schedule Experts**: Book short talks with industry or internal experts.
3. **Find the Right Space**: Reserve an accessible room with whiteboards, good acoustics, movable furniture, and accommodations.
4. **Gather Supplies**: Stock up on sticky notes, markers, snacks, and water.
5. **Establish Rules**: Set ground rules early (e.g., gadgetless environment).
6. **Plan Introductions**: Use relevant icebreakers to build team comfort and user empathy.
7. **Post-Sprint Planning**: Assign note-takers and photographers to document ideas, sketches, and sticky notes for post-sprint documentation.

## 5. Components of a Design Sprint Brief

| Component | Description |
| --- | --- |
| **Sprint Challenge** | An inspiring, clear, real, time-bound challenge statement |
| **Key Deliverables** | High-quality outputs expected by the end of the sprint (e.g., complete interactive prototype) |
| **Logistics** | When, where, participant list, and designated **Sprint Leader** |
| **Approvers** | Executive or stakeholder sign-offs needed before launch |
| **Resources** | Assigned engineering or design development resources post-sprint |
| **Project Overview** | Current status, roadblocks, early wins, and launch timeframe |
| **Sprint Schedule** | An hour-by-hour agenda for all 5 days |

## 6. Sprint Retrospective

- **Definition**: A collaborative critique and reflection meeting held immediately after the sprint wraps up while thoughts are fresh.
- **Core Purpose**: Empowers the team to continuously improve, avoid repeating past mistakes, and foster better communication.

### Two Key Questions

1. *What went well?*
2. *What can be improved?*

## 1. Overview of Design Thinking Framework

- **Definition**: A user-centered conceptual tool and framework that provides guidance and structure for solving real user problems.
- **Nature of the Process**: Non-linear and **iterative**; designers move back and forth between phases based on feedback and research findings.

### Core Principles Across All UX Frameworks

- Focus on the user.
- Address user problems directly.
- Collaborate with cross-departmental teams.
- Validate and iterate designs.

---

## 2. Incorporating Business Requirements

- **Context**: Real-world projects typically start with business requirements set by stakeholders (for-profit, non-profit, government) before moving into design thinking.

### Key Components

| Component | Description |
| --- | --- |
| **Business Goals** | Target audience, desired outcomes, and product vision |
| **Business Parameters** | Constraints like budget, timeline, scope, specific tools/systems, and technical standards |

- **Role**: Act as guardrails, filters, and creative constraints that guide designers through every stage of the design thinking process.

---

## 3. Phase 1: Empathize with Users

- **Goal**: Deeply understand user feelings, thoughts, needs, and environmental context without bias or assumptions.
- **Role of Business Requirements**: Validates, updates, and expands existing user assumptions using actual research while staying within timeline and budget limits.

### Primary Methods

| Method | Description |
| --- | --- |
| **Interviews** | Questionnaires/surveys, in-person, phone, or video interviews |
| **Empathy Maps** | Visual processing tool answering 5 questions about users: *Who are they? What do they say, think, do, and feel?* |
| **User Personas** | Fictional characters representing key user segments to humanize user data during design decisions |

---

## 4. Phase 2: Define Users' Needs

- **Goal**: Analyze empathy research to identify and articulate the most critical user problems to solve.

### Key Artifacts

- **User Stories**: One-sentence narratives written from a persona's perspective.
  - *Template*: "As [type of user], I want to [action] so that [benefit]."
- **User Journeys**: Mapping out the step-by-step series of experiences/tasks a persona completes to achieve their goal.
- **Problem Statements**: Clear descriptions of user needs written from the designer's perspective.
  - *Template*: "[Persona] is a [type of user] who needs [type of UX] because [benefit]."

## 5. Phase 3: Ideate Solutions

- **Goal**: Brainstorm as many creative, out-of-the-box, and judgment-free solutions as possible before filtering or evaluating.

### Brainstorming Techniques

| Technique | Description |
| --- | --- |
| **"How Might We?" (HMW)** | Reframing problem statements into optimistic questions to inspire solutions |
| **Rapid Sketching ("Crazy Eights")** | Visual ideation technique where designers sketch 8 distinct ideas in 8 minutes |
| **Competitive Audits** | Analyzing competitors' products to identify market gaps, strengths, and weaknesses |
| **SCAMPER** | Idea generation acronym: **S**ubstitute, **C**ombine, **A**dapt, **M**odify, **P**ut to another use, **E**liminate, **R**earrange |

> **Business Check**: Filtering generated ideas against budget, scope, and technical feasibility.

---

## 6. Phase 4: Prototype Solutions

- **Goal**: Build early functional or visual models of the product to demonstrate functionality and gather feedback.

### Key Artifacts & Processes

| Artifact | Description |
| --- | --- |
| **Information Architecture (IA) & Sitemaps** | Outlining a product's structural hierarchy (importance/grouping) and navigation sequence (user order) |
| **Wireframes** | Basic structural layouts using shapes, lines, and placeholder text (*Lorem Ipsum*). Can be paper sketches or digital 2D wireframes |
| **Low-Fidelity (Lo-Fi) Prototypes** | Interactive models built from basic wireframes to test navigation and feature flow early on |
| **High-Fidelity (Hi-Fi) Prototypes** | Detailed, realistic models incorporating complete visuals, content, and interactivity to closely mimic the final product |

---

## 7. Phase 5: Test Solutions

- **Goal**: Evaluate prototypes with users to uncover usability issues (pain points), validate design decisions, and refine functionality before developer handoff.

### Testing Plan Fundamentals

| Question | Details |
| --- | --- |
| **Who** | Informal testers early on; target users matching personas for main testing rounds |
| **What/Where/When** | In-person or virtual user tests balanced with business parameters |
| **Why** | Validate ideation assumptions and fix usability issues |
| **How** | Ensure testing environment and tools are accessible, inclusive, and equipped with assistive technology |

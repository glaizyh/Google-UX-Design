## 1. User Stories

- **Definition**: A fictional, one-sentence story told from a persona's point of view to inspire and inform user-centered design decisions. (Also called scenarios or user cases.)
- **Formula**: "As a [type of user], I want to [action] so that [benefit]."

### Parts of a User Story

| Part | Description |
| --- | --- |
| **Who** (Type of User) | Describes who you are designing for and their specific situation |
| **What** (Action) | Describes the specific task or action the user hopes to achieve to avoid a pain point |
| **Why** (Benefit) | Defines the meaningful personal benefit or outcome the user gains |

- **Key Benefits**: Prioritizes design goals, unites cross-functional teams around a shared objective, inspires empathetic decisions, and humanizes stakeholder pitches.

## 2. Happy Paths vs. Edge Cases

- **The Happy Path**: A user story where everything goes as expected, and the user achieves their goal seamlessly without obstacles.
- **Edge Cases**: Rare situations or unexpected problems that disrupt the standard user experience and block the happy path (e.g., an international customer unable to check out due to a mandatory "US State" field).

### Pro Tips to Prevent Edge Cases

1. Build user stories and personas that account for vulnerable users and unique constraints.
2. Perform thorough project reviews from the user's perspective before launch.
3. Use wireframes early on to spot potential roadblocks and visual pain points.

## 3. User Journey Mapping

- **User Journey**: The series of experiences a user goes through to achieve a specific goal.
- **User Journey Map**: An illustrated outline showing the sequence of interactions, tasks, and emotional states a persona experiences.

### Analogy

| Artifact | Storytelling Equivalent |
| --- | --- |
| **Persona** | Character |
| **User Story** | Plot |
| **Journey Map** | Story Outline |

### 4 Benefits of Journey Mapping

1. Helps designers create obstacle-free navigation paths.
2. Reduces **designer bias** by keeping the focus strictly on the persona's thoughts and feelings rather than the designer's.
3. Uncovers new, non-obvious pain points.
4. Highlights clear opportunities for product improvement.

### Steps to Map a Journey

1. *Identify the Primary Task*: Define the starting goal (e.g., traveling to a destination).
2. *List Main Tasks*: Detail the main high-level steps required.
3. *Detail Sub-tasks*: Break down smaller steps under each main task.
4. *Track Emotional Journey*: Map emotional highs/lows (confusion, frustration, excitement) at each step.
5. *Identify Improvement Opportunities*: Add features or fixes that address the emotional and physical roadblocks.

## 4. Accessibility in User Research & Artifacts

- **Inclusion Scope**: Accessibility covers permanent, temporary, and situational limitations across all user journeys.

### Types of Limitations

| Type | Examples |
| --- | --- |
| **Permanent** | One arm / Blind / Deaf |
| **Temporary** | Sprained wrist / Wears glasses / Ear infection |
| **Situational** | Holding a newborn / Distracted driver / Working in a loud room |

### Accessibility Design Considerations Across Senses

| Sense | Considerations |
| --- | --- |
| **Touch** | Single-arm operation, double-tap protection, customizable layouts, one-handed keyboard modes |
| **Sight** | High-contrast colors, customizable fonts/spacing (helpful for dyslexia), screen-reader alt text, avoiding reliance on color alone for warnings |
| **Hear** | Haptics (vibrations) and notification lights instead of audio cues alone; closed captions; in-app text messaging |
| **Speak** | Real-Time Texting (RTT) during calls, text alternatives for speech recognition systems, emoji/image options |
| **Learn / Cognitive** | Straightforward, consistent navigation; pairing text with graphics/audio; simplified layouts |

> **Keyboard Navigation & ATs**: Supporting keyboard input (e.g., *Tab* and *Enter*) is an ADA compliance requirement that also enables assistive technologies like switch devices.

## 5. The Curb-Cut Effect

- **Definition**: A phenomenon describing how products and features originally designed for people with disabilities end up benefiting *everyone*.

### Real-World Examples

| Example | How It Helps Everyone |
| --- | --- |
| **Curb Cuts** | Sloped sidewalk ramps originally built for wheelchairs also help parents with strollers, bicyclists, skateboarders, and delivery movers |
| **Crosswalk Signals** | Auditory beeps and tactile sidewalk pavement designed for visually impaired users help distracted pedestrians on smartphones |
| **Closed Captions** | Designed for deaf users, but benefits people in noisy venues (sports bars) or non-native speakers learning a language |
| **Removing Session Timers** | Lengthening or removing strict inactivity timeouts helps neurodiverse users as well as busy parents, senior citizens, and people searching for payment cards |

## 1. Psychology in Design & Human Factors

- **The Human Factor**: The range of variables humans bring to product interactions.
- **Historical Context**: Prior to WWII, design attempted to fit humans to machines. During WWII, complex military machinery made it necessary to adapt machines to human limits and skill levels.
- **Common Human Factors**: Impatience, limited concentration, limited memory, needing motivation, needing analogies, changes in need, prejudices, fears, making errors, and misjudgment.
- **TL;DR Example**: Short for "Too long; didn't read"; a brief summary in long emails designed to address human impatience and limited memory.

## 2. Key Psychological Concepts for UX

| Concept | Description | UX Application |
| --- | --- | --- |
| **Mental Models** | Internal maps that allow humans to predict how something will work based on prior experience. A mental model breaks when an outcome does not match expectations (e.g., opening a door only to find a solid brick wall behind it) | — |
| **Feedback Loops** | The outcome a user gets at the end of an action | *Positive feedback*: confirmation that an action worked (e.g., a light turning on when flipping a switch). *Negative feedback*: confirmation that nothing happened or the action failed |
| **Nostalgia** | Reissuing classic packaging or designs to form an emotional connection with human users | — |
| **Von Restorff Effect** (Isolation Effect) | When multiple similar objects are present, the one that differs from the rest is most likely to be remembered | Primary Call-to-Action (CTA) buttons use distinct shapes or bright colors to stand out from other page elements |
| **Serial Position Effect** | People tend to remember the first few and last few items in a list, while items in the middle blur | Positioning key navigation items on the far left or far right of top navigation bars |
| **Hick's Law** | The time it takes to make a decision increases proportionally with the number and complexity of choices | Keeping choices concise to avoid overwhelming users with decision fatigue |

## 3. Defining Problem Statements

- **Definition**: A clear description of the user's need that should be addressed.
- **Core Purpose**: Establishes goals, highlights constraints, defines deliverables, and creates benchmarks for success.
- **Key Characteristics**: Human-centered, broad enough for creative freedom, and narrow enough to be solved by a practical design solution.

### The 5 Ws and H Framework

| Question | Focus |
| --- | --- |
| **Who** | Who is experiencing the problem? |
| **What** | What pain points are you trying to solve? |
| **Where** | Where is the user physically when using the product? |
| **When** | When in the user journey does the problem occur? |
| **Why** | Why is solving this problem important to the user's life? |
| **How** | How do users reach their goals through the product? |

### Problem Statement Formula

> **[User Name]** is a/an **[User Characteristics]** who needs **[User Need]** because **[Insight]**.

## 4. Hypothesis Statements

- **Definition**: An educated guess about what the solution to a design problem might be.

### Key Formats

| Format | Template | Notes |
| --- | --- | --- |
| **If/Then Formula** | "If [action], then [outcome]." | Focuses directly on the specific actions and desired benefits of the user |
| **We Believe Formula** | "We believe that [action/solution] for [user] will allow them to [outcome]." | Incorporates the team's perspective while maintaining empathy |
| **Flexible Format** | Adaptable phrasing | Used when standard formulas feel unnatural |

- **Multi-Hypothesis Approach**: One problem statement can have multiple hypothesis statements, as there are many potential solutions to a single problem.

## 5. Value Propositions

- **Definition**: A short, clear summary explaining why a consumer should use a product or service instead of alternatives.

### Two Core Questions

1. *What does your product do?* (Explains the product offering clearly.)
2. *Why should the user care?* (Explains how the product solves specific user pain points.)

### 4 Steps to Build Value Propositions

1. **List Features & Benefits**: Brainstorm all features and benefits without holding back.
2. **Categorize Value**: Group the features into broad user value categories (e.g., accessibility, cost, reliability) and discard non-valuable filler.
3. **Connect to Persona Needs**: Pair persona pain points directly with specific value propositions.
4. **Identify Unique Value Propositions (UVPs)**: Cross-reference competitor offerings and remove features already met by competitors to highlight what makes your product unique.

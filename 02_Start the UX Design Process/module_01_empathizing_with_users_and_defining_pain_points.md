## 1. Understanding Empathy in UX Design

- **Core Concept**: Empathy is the ability to understand and share someone else's feelings or thoughts in a situation.
- **Overcoming Assumptions**: UX research uses empathy to replace assumptions with what real users *actually* need and want solved.

### Distinctions

| Term | Description |
| --- | --- |
| **Pity** | Feeling sorry for someone; carries condescending overtones |
| **Sympathy** | Showing concern or compassion without feeling or sharing the emotion itself |
| **Empathy** | Sharing the user's mental and emotional experience; experiencing the product as the user does |

### 6 Tips for Empathetic Design

1. **Ask Lots of Questions**: Use open-ended questions beginning with *what*, *how*, and *why*.
2. **Become More Observant**: Watch physical cues, body language, and facial expressions during interviews.
3. **Be an Active Listener**: Fully concentrate on and remember user input without getting distracted by what to say next.
4. **Request Objective Input**: Seek unbiased feedback from a wide, diverse range of actual users rather than supportive friends.
5. **Have an Open Mind**: Set personal biases aside to refrain from complicating feedback with your own opinions.
6. **Keep Current on UX Research**: Follow industry researchers and online communities as human psychology insights evolve.

## 2. User Problems & Pain Points

- **Goal**: Identify clear, actionable user problems to set realistic goals and avoid arbitrary expectations.
- **Types of Needs**: Anticipate both *known needs* (e.g., flip phone battery life) and *unknown needs* (e.g., smartphones before 2007).
- **Definition of Pain Points**: Any UX issues that frustrate the user and block them from getting what they need.

### 4 Categories of Pain Points

| Category | Description | Example |
| --- | --- | --- |
| **Financial** | Money-related user struggles | Paywalls interrupting online articles |
| **Product** | Quality or functional issues with the physical or digital product | Norman Doors |
| **Process** | Obstacles encountered while progressing from point A to point B | Checkout failures on e-commerce sites |
| **Support** | Lack of assistance or answers when users encounter questions | Hidden customer service contacts |

## 3. Empathy Exercises & User Interviews

- **Pre-Interview Empathy Exercise**: Imagining perspective and anticipating participant answers using fictional **user profiles** (short biographies used before formal interviews) to validate and refine interview questions.
- **User Personas vs. User Profiles**: User profiles are informal tools for early empathy exercises, whereas user personas are formal assets distilled from real user data after interviews.

### 4 Steps to Conduct User Interviews

1. **Meet the Participant**: Build rapport, show gratitude, review legal consent/recording release details, collect demographic data, and emphasize that there are no wrong answers.
2. **Conduct the Interview**: Maintain professional etiquette and ask **open-ended questions** starting with *why* or *what* (avoid simple yes/no questions).
3. **Take Notes**: Highlight compelling direct quotes, document non-verbal observations (mood, body language), and record audio/video with permission.
4. **Wrap Up**: Offer time for final thoughts, express gratitude, give a warm goodbye, and provide any promised incentives.

## 4. Empathy Maps

- **Definition**: An easily understood 4-quadrant chart breaking down interview findings around a user placed in the center.

### The 4 Quadrants

| Quadrant | Description |
| --- | --- |
| **Says** | Verbatim, direct quotes captured from the interview |
| **Thinks** | Inferred thoughts and underlying attitudes observed through tone, body language, or expressions |
| **Does** | Actions, behaviors, or physical steps taken by the user |
| **Feels** | Explicit or inferred emotions expressed during the session (e.g., worried, frustrated, sad) |

### Types of Empathy Maps

| Type | Description |
| --- | --- |
| **One-User Empathy Map** | Records feedback from a single individual interview session |
| **Aggregated (Multiple-User) Empathy Map** | Combines data from multiple individual maps to represent an entire user segment and identify common themes |

## 5. User Personas

- **Definition**: Fictional characters whose goals and characteristics represent a larger **user group** (a set of people with similar interests, goals, or concerns).

### Components of a Persona

- Photo and biographical sketch (age, location, family, occupation).
- Demographic data and tech literacy/comfort level.
- Professional goals, daily tasks, and a representative quote/catchphrase.

### Value of Personas

| Value | Description |
| --- | --- |
| **Build Empathy** | Humanize complex statistical data by putting a face to the user |
| **Tell Stories** | Make client/stakeholder presentations engaging and memorable |
| **Stress-Test Designs** | Allow teams to evaluate features against varying user needs across a set of diverse personas |
